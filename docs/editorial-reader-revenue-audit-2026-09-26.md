1. 첫 문단 직접 답변, 연도·지역·예외 보존, 공식 첨부자료까지 작성자가 확인하는 원칙.
2. 고정 글자 수, 채우기용 서론·FAQ, 독자에게 자료 확인을 떠넘기는 문구를 배제.
3. 상황별 분기, 실행 순서에만 STEP, 공식 기능 목적지만 CTA, 하단 출처 목록.

5. draft 기본, 별도 의미 검토와 구조화 검사, 공개 승인 분리.
6. 관련 글은 검토된 plan.related_posts로 최대 2개 지정할 수 있다. 기능 신설보다 실제 활용이 우선이다.

## 공개 화면에서 확인한 개선 후보

### 1. 첫 답변까지의 거리를 줄이기

확인: #470 데스크톱 첫 화면에는 큰 대표 이미지와 제목 시작 부분이 보이고 요약은 화면 아래다. 390×844 viewport에서 페이지 최상단 기준 요약 상자 top은 약 791px, CTA 상자 top은 약 1,843px였다. 제목 앞 대표 이미지, 제목, 상단 공유 기능, 요약과 overview 표가 누적된다. 수치는 이 브라우저·시점의 관찰값이다.

제안: 본문 대표 이미지 높이를 줄이거나 제목·핵심 답변 뒤로 이동하는 시안을 비교한다. 목록 썸네일은 별개로 관리한다. 첫 요약은 결론과 핵심 조건, 표는 분기·비교 정보를 담당하도록 중복을 줄인다. 중요한 적용 범위를 삭제하면서 짧게 만들지 않는다. 상단 공유 기능은 이용 데이터를 보고 축소한다.

기대 효과는 가설: 독자 판단과 실행이 빨라지고 스크롤 부담이 줄 수 있다. 체류 시간이나 수익 상승은 미확인이다.

### 2. 최신순 이동을 독자의 다음 과제로 보완

확인: #470 하단 이전·다음 글은 도시가스 경감과 남진 콘서트다. #231 하단 이동 링크도 남진 콘서트로 연결된다. 두 글에 본문 관련 글 블록은 관찰되지 않았다. 사이드바는 최신 글 중심으로 여러 주제를 섞어 보여준다.

제안: 정규 검토 경로의 related_posts 1~2개를 우선 사용한다. 예를 들어 숨은 돈 찾기, 자동차 생활, 공공요금 절감처럼 독자의 문제를 중심으로 묶고, 관련성이 명확할 때만 연결한다. '관련 글'의 링크 라벨은 다음에 해결할 질문을 표현한다. 예: '계좌 외에 통신 미환급액도 확인하려면'. 대상 글의 현재 공개 상태·유효성·실제 도착 내용 확인이 먼저다.

코드상 자동 추천 fallback은 로컬 published_posts.json과 제목 단어 겹침을 사용한다. 단어가 다르지만 문제상 연관된 글을 놓칠 수 있고, 렌더 시 저장한 링크는 이후 대상 글 상태 변화를 스스로 반영하지 않는다. 명시적 검토 링크와 주기적 링크 점검을 우선하며 최대 개수 확대부터 하지 않는다. 테마 이전·다음 글과 renderer 관련 글은 서로 다른 기능이다.

### 3. 글별 포맷과 목록 발췌문의 일관성

확인: #470에는 현행 '목차', 일반 절/절차 구분, 표와 FAQ가 있다. #345에는 구형 '핵심 목차 한눈에 보기', 출처까지 포함한 목차, 상단 동일한 무게의 CTA 4개, FAQ 주변 빈 paragraph가 보인다. 홈페이지 #345 발췌에는 '한눈에 보기', '바로 예매…', 버튼 라벨이 들어간다.

제안: 유입이 있는 기존 글부터 현행 포맷으로 점진적으로 이관한다. 발췌는 답변 lead에서 가져오되 목록에서는 읽기 쉬운 길이로 구성한다. 신규 renderer를 바꾸는 것과 기존 저장 HTML을 이관하는 것은 별개 작업이다. WP 직접 편집으로 검사 경로를 우회하지 않는다.

### 4. FAQ를 추가 판단 가치 중심으로 정리

확인: #470의 FAQ 5개는 본문에서 이미 설명한 기간·검사 종류·비용·과태료·민간 가격을 다시 답한다. 자체 완결적인 답변이라는 장점도 있다.

제안: 모든 반복을 제거하지 말고 오해하기 쉬운 판단 질문을 남긴다. '30일 넘으면 바로 60만원인가요?', '검사 종류를 선택하나요?' 같은 문항은 유지 가치가 있다. 단순 비용 재진술은 표와 역할이 겹치는지 검토한다. FAQ 개수를 의무화하지 않고 새로운 예외·대안·오해 해소가 있는지를 검토표에 추가한다.

### 5. 정책의 최신성·수명·신뢰 표시

확인: 현행 지침의 evergreen 60%/seasonal 40%는 지향 비율이며 검색 수요나 광고 성과 근거가 아니다. 예시에는 '알뜰교통카드' 같은 명칭이 포함된다. 홈페이지에 9/27까지 활용되는 추석 글 여러 편이 있고, 표본 글의 업데이트 표시는 모두 9/26이다. 푸터는 '가장 빠르고 정확하게', '모든 콘텐츠는 … AI 팩트 검증 …'이라는 표현을 사용한다.

제안: 명칭·상품을 상시 주제 예시로 고정하기보다 반복되는 독자 문제를 기준으로 설명하고, 주제 선정 시 서비스 존속·개편을 검증한다. 이 감사에서는 해당 서비스의 최신 상태를 별도 검증하지 않았다. 종료 글은 글별로 지난 일정 보존/새 일정 갱신/상시 절차 개편을 선택하고 홈 추천에서 제외하는 기준을 둔다. 수정일과 공식 정보 재검토일을 구분하고, 실제 검토 이력이 있을 때만 검토 정보를 표시한다. 푸터 최상급·전체 보증 문구는 검증 가능한 편집 절차와 정정 경로 설명으로 바꾸는 것을 권고한다.

## 광고와 측정 원칙 제안

Google AdSense는 광고를 메뉴·탐색·다운로드 링크로 착각하게 배치하거나 클릭을 직접 독려하는 것을 금지한다. 목표는 유용한 콘텐츠와 정상 광고 노출에서 발생하는 수익으로 정의한다.

- 첫 답변, CTA, 목차, 표 스크롤, 공유 버튼의 사용을 방해하지 않도록 광고와 분리한다.
- 광고 실험 후보는 완료된 정보 절 사이와 본문 하단이다. 고정 간격/개수가 정답이라는 뜻은 아니다. 실제 자동 광고 설정·표시를 확인한 뒤 하나씩 실험한다.
- #470의 관찰 세션에서 ins.adsbygoogle와 iframe은 0개였다. 이것은 광고 미승인/비활성화/전체 방문자 미노출의 증거가 아니다. 계정 상태·수익·노출 설정은 미확인이다.
- 기준선: 글별·기기별·유입 경로별 평균 참여 시간, 다음 글 이동률, 공식 CTA 클릭률, 가능한 범위의 본문 구간 도달, AdSense page RPM/노출/수익. CTA 클릭은 신청 완료가 아니며 스크롤은 이해의 증거가 아니다.
- 블로그 한 페이지에서 세션이 끝나도 공식 조회·예약 목적을 달성했을 수 있다. 체류 시간과 이탈률 하나로 실패 판정하지 않는다.
- QA UTM과 로그인 사용자는 분석에서 별도 처리한다. Direct/미표시 트래픽을 사람 또는 봇이라고 단정하지 않는다. 자체 광고를 클릭해 확인하지 않는다.
- 2~4주를 첫 관찰 기간으로 둘 수 있지만 방문량이 적으면 충분한 결론을 내리지 못할 수 있다. 동일 주제·기기·유입을 비교하고 시즌 종료 효과를 분리한다. 가능하면 대조군을 두며 단순 전후 비교는 인과 증거로 과장하지 않는다.

## 실행 우선순위

1. 기초 지표 확인, 관련 글 1~2개 연결, 오염된 목록 발췌 점검.
2. 자동차검사 같은 상시 글 3~5편에서 이미지 높이·요약 중복·FAQ를 시험. 구조/CSS가 바뀌면 정해진 전체 화면 QA 적용.
3. 시즌 종료 처리, 검토일 관리, 푸터 신뢰 문구 개선안 검토.
4. 실제 광고 설정 확인 후 독자 행동과 RPM을 함께 보면서 배치 실험.
5. 검증된 정보의 체크리스트 등 간단한 독자 도구부터 검토. 계산기·자격 판정은 현재 renderer의 원 단위 덧셈만 허용하는 계약을 넘어가므로 별도 설계·공식 규칙·경계값 테스트가 필요하다.

## 1~4번 개선 적용 (2026-09-26), 중단 후 마무리 (2026-09-27)

### 승인 범위와 구현

사용자가 1~4번 개선 적용을 지시했다. 작업을 공통 화면·지침 변경과 기존 공개 글의 표현·중복 정리로 분리했다. 공유 정책을 먼저 안정화한 뒤 글별 후보를 한 번씩 독립 검토하고 정규 update-existing 경로로 갱신했다. 새 글 공개나 광고 설정 변경은 없다.

- 첫 답변: 단일 글의 대표 이미지를 자르지 않고 모바일 최대 120px, 데스크톱 최대 200px로 표시한다. 제목·본문·상단 공유 영역의 간격을 줄인다. 목록 썸네일은 그대로 유지한다. lead는 핵심 답과 필수 조건을 유지하며 상세표의 모든 숫자를 반복하지 않도록 지침에 명시했다.
- 관련 읽기: 독자가 다음에 해결할 다른 과제에 맞는 공개 글 1~2개를 검토한다. 관련 글 블록이 있는 단일 글만 테마의 날짜순 이전·다음 이동을 숨긴다. 블록이 없는 글과 목록의 기존 이동은 유지한다.
- 구형 서식: #345를 현행 구조화 renderer의 한눈에 보기·공식 행동 경로·단일 목차·FAQ·출처 형식으로 갱신했다. 정규 updater가 lead 기반 발췌문을 저장해 목록에 공유 문구·목차가 노출되지 않도록 했다. 별도 수동 발췌문은 보존하는 기존 로직을 사용한다.
- FAQ: 숫자를 그대로 반복하는 질문을 줄이고 오해·예외를 해결하는 질문을 남겼다. 최소 개수를 채우도록 강제하지 않는다.
