## 범위·보호 조치

## 원인: 기존 팩트체크가 실패한 이유
1. `fetched_at`은 문서를 다운로드한 시각일 뿐 **제도 시행 연도·개정일이 아니다**. 오래된 공식 발표를 오늘 수집해도 24시간 이내 ‘신선한 자료’로 통과했다.
2. `sha256` 검증은 수집 원문의 변조만 검출하고, `quote_not_in_source`와 숫자 검사도 **틀린 공식 원문에 충실한 인용**을 통과시켰다. 예: 과거의 50점 상한을 인용한 세금포인트 원고.
3. 작성/검토 모델 호출은 분리돼도 기본 설정상 같은 모델을 사용하고 동일한 출처 묶음을 검토했다. 서로 다른 최신 출처를 직접 재검색하는 독립 검증 단계는 없었다.
4. #101 같은 기존 수동 제작 필러 글과 #63 등 레거시 공개 글은 최신 구조화 bundle 검증으로 소급 재검토되지 않았다. `PublisherAgent`는 새 글을 draft로 만들지만 WordPress 관리자·수동 수정은 차단하지 못한다.
5. 중복 검사는 제목 토큰과 공식 URL 일치 중심이어서 기초연금·독감의 질문이 겹치는 별도 URL 글을 충분히 포착하지 못했다.

## 예방 조치 및 코드 동작
- 신규 `agents/critical_facts.py`: 2026년 기초연금·세금포인트·인플루엔자 주제에 최신 정부기관 도메인과 올해 기준값·적용 코호트·알려진 오류 차단을 추가. 후속으로 숨은 보험금 즉시 지급·규모 과장, 본인부담상한제 연도 없는 상한액/평균 환급액, 전기차 무료 충전·전력/에너지 단위 혼동을 탐지하는 좁은 차단 규칙과 회귀 테스트 3개를 추가했다. `agents/editorial.py::validate_bundle()`에서 모델 검토와 별개로 실패시 draft 생성을 보류.
- `published_content_risks()`는 레거시 공개 글에서 알려진 위험 패턴을 찾는 읽기 전용 보조 감사다. 거짓 음성·거짓 양성이 가능하며 정확성 인증이 아니다.
- `main.py` 단일 `--category tax`를 허용. 성공 `published` 통계는 내부 키 이름과 다르게 실질적으로 **임시글 생성 건수**이며 운영 보고서에서 그 의미를 명확히 한다.
- 실제 모델 선택: 기본 `gemini-3.5-flash`; 429/503인 경우 `gemini-3.6-flash`, 그다음 `gemini-3.5-flash-lite`. Quota Tracker는 공급자 잔여량 API가 아니라 UTC 날짜로 기록한 **로컬 추정**이다.
- `list-drafts`는 WP-CLI의 실제 draft 목록을 읽는 방식으로 구현했다. `promote-draft`는 `--confirm-publish`를 요구하고 리뷰된 bundle·초안 내용·검토/출처 기한·현재 공식 원문 해시를 모두 재검사한다. 레거시·수동 작성 초안 또는 원문 변경 건은 자동 승격하지 않으며, 실제 콘텐츠 공개 테스트는 실행하지 않았다. WhatsApp의 명시적인 `/publish ID`에만 이 확인 플래그를 연결했다.
- 정기 백업: 운영 서버의 암호 하드코딩된 DB 전용 스크립트를 환경변수/Docker 설정에서 비밀값을 읽는 통합 스크립트로 교체. DB, uploads, configs, manifest 포함 15MB 통합 백업 생성; 세 구성요소 SHA256 검증 전용 `restore_backup.sh --verify-only` 성공. 운영 데이터 복원을 실행해 복구 성공을 증명한 것은 아니다. 보관 디렉터리 0700/아카이브 0600.
