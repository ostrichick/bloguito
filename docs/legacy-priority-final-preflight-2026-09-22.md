## 출처 해시가 실제 정책 변경 없이 흔들리던 오류 해결

- 보건복지부 보도자료의 `.hit` 조회수 메타데이터만 제거하도록 수집기를 한정하고 기사 본문의 숫자/조회수 서술은 유지했다. 이 문제로 #55·#79·#101의 기존 사전검사가 오탐지했던 소스 드리프트를 해결하고, 변동하지 않은 원문 스냅샷으로 다시 `sources → review → check`를 진행했다.
- 목포시 건강 게시판의 `.view_titlebox`에 있는 `조회수`의 숫자와 첨부 다운로드의 `hit` 수만 **정확한 URL 경로·DOM 구조에서** 제외한다. 첨부 **파일 크기·이름·본문·게시일과 백신 사실은 그대로 해시**에 넣었다. #103에서 실제로 관찰한 이전/신규 차이는 게시판 조회수 `336→338`, 다운로드 조회수 `270→276`뿐이며 정규화 뒤에는 문서 내용이 바뀌지 않은 4개 공식 URL의 해시가 재조회와 일치했다. 단위검사는 숫자가 있는 **기사 본문이 바뀌면 SHA가 변하고, 첨부 파일 크기가 바뀌어도 SHA가 변함**을 확인한다.
- 시간 검증기는 기초연금의 **2026년 금액 기준 적용기간**과 예방접종의 **2026~2027절기**를 허위 ‘신청 접수 중’ 상태로 취급하지 않으며, ID가 다른 글·근거의 날짜 위조·기간 초과 시 실패한다. 기존 글에 대한 보수적 한정이며 신규 글이나 다른 지역에 적용하는 만능 우회로가 아니다.

## 실제 Edge 브라우저에서 네 원고 검사

`tmp/legacy_audit_20260922/priority-prime/browser_priority_qa.mjs`가 **격리된 Edge 한 인스턴스**를 재사용해 실제 최종 선택 원고(#55·#79·#103은 `priority-prime`, **#101은 추가 20% 감액 설명이 들어 있는 `content-worker1/approval-101-20260922-r2/`**)를 독립 문서에 넣고, **360×800·390×800 CSS 픽셀 및 데스크톱 1280×900에서 CSS `zoom:200%` 근사**를 검사했다. 총 **4편 × 3상태 = 12화면 모두 PASS**, 문서 가로 넘침 0, 깨진 이미지 0, 콘솔 오류 0, 각 목차는 1개·앵커 누락 0이었다. #103의 기관 표는 caption·열/행 scope·키보드 초점이 있으며 좁은 화면에서 실제 방향키 입력으로 내부 가로 스크롤이 이동했다. #101의 **선택한 r2 원고에는 표가 없고 지역별 공제액을 근거 있는 문단으로 직접 설명**한다. 표 3구간이 있는 별도의 `priority-prime/approval-101-ready/` 대안도 독립 검사에 통과했으나 이를 최종 선택본과 혼합하여 승인했다고 주장하지 않는다. 전체 JSON은 `priority-browser-results.json`, 모바일 캡처 8장은 `qa-priority-{ID}-{360|390}.png`, 로컬 전체 본문 미리보기는 `preview-{ID}.html`이다. 실제 방향키 검증 후 스크롤을 왼쪽으로 되돌려 다시 촬영했고 #103·#101 화면을 육안 확인했다. 브라우저 **네이티브 200%**, 스크린리더·실기기 터치, 운영 테마 설치 후 브라우저 QA, 로그인 뒤 신청/모의계산 성공은 통과했다고 주장하지 않는다.

## 자동 게이트 통과와 별개인 #103 수동 발행 차단

목포시 **9월 16일 보건소 공지**의 자체사업 취약계층 연령은 `15~65세`, **9월 18일 시 보도자료**는 `15~64세`로 상충한다. 현재 검토 원고는 자체사업 상한 숫자를 임의로 단정하지 않고, 별도의 국가사업 65세 이상 대상과 맞추어 구분했다. 따라서 자동 `ready`와 6개 의미 검사 통과에도 불구하고 **65세 목포시민의 자체 보건소 대상·어린이 이외 위탁의료기관 명단을 공식 확인하기 전에는 #103 공개 적용을 수동 차단**한다. 어린이 위탁기관 6곳을 임신부·어르신 및 자체사업 전원에 적용되는 시설이라고 일반화하지 않는다. 목포시 공지의 전체 대상별 위탁기관 HWP와 실제 대상/기관 대응은 아직 독립 대조하지 못했다. 이 불확실성을 글에 숨기고 전 대상 이용 가능이라고 말하지 않는다.

## 승인 대상과 롤백

**#55·#79·#101:** 기술·독립 검토는 완료됐지만 **각 글의 변경안에 대한 별도 사용자 승인 전** 운영 수정 금지. **#103:** 기술 검사는 완료했으나 위 수동 차단까지 해소한 뒤에만 글별 승인을 요청한다. 승인 직전 공식 URL 전부 재조회, 리뷰/소스 24시간 이내, **전체 WordPress 상태 목록**, 해당 글 현재 저장 본문 SHA·제목·slug·상태·발췌문을 새로 조회하여 불일치하면 정지한다. 해당 ID가 명시된 정상 `editorial_cli.py update-existing`만 사용하고 임시 PHP/WP-CLI 직접 편집으로 검토를 우회하지 않는다. 업데이트 뒤 운영 브라우저에서 본문·표·목차·공식 행동 경로와 360/390/네이티브 200%를 재검증한다.

복구할 때는 **현재 본문의 SHA가 방금 승인 적용한 후보와 동일한지** 먼저 확인한다. 다르면 그 사이 다른 사람의 수정이 있으므로 강제 복구·병합 금지. 일치하면 별도 승인된 복구 절차에서 각 폴더의 원본 전체 백업 중 `post_content`·이전 발췌문을 원상 복원하고 원래 제목·slug·게시일·상태·이미지·분류 보존을 검증한다. **이번 작업은 복구를 실제 실행하거나 운영 서버에 쓰지 않았다.**
