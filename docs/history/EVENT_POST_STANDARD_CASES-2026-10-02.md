# 행사 포스트 표준 작업 사례 기록

이 문서는 `EVENT_POST_STANDARD.md`의 현행 규칙이 만들어진 배경을 보존하는 역사 기록이다. **현재 작성 규칙은 정본인 `docs/EVENT_POST_STANDARD.md`를 따른다.** 이 파일의 사례·숫자·과거 예외를 새 글의 규칙으로 직접 승격하지 않는다.

## 대전 Draft #641

- Gemini 초안을 실제 공식 자료와 대조하면서 날짜·장소만 있는 행사 소개는 방문 판단에 부족하다는 문제가 확인됐다.
- 행사별 신청 CTA는 상단 공통 버튼이 아니라 해당 행사 설명 바로 뒤에 두는 section scope 원칙의 기준 사례가 됐다.
- `탄동천 탐사 신청`처럼 실제 행동이 가능한 링크와 일반 공식 정보 페이지를 구분해야 한다는 원칙이 강화됐다.

## 전주 #621

- 여러 행사장을 하나의 카카오맵에서 비교하는 UX를 검증한 기준 사례다.
- 전체 행사장 map과 각 행사별 위치 카드는 역할이 다르므로 둘 다 유지하는 방향이 채택됐다.
- 이후 도시별 one-off 지도 구현 대신 공통 renderer/component 재사용 원칙으로 정리됐다.

## 부산·대구·광주·세종 행사 글

- 표 안의 날짜를 길게 쓰면 모바일 가독성이 크게 떨어져 `M/D(요일)` 중심의 짧은 표기로 정리됐다.
- 대상 월과 직접 관계없는 장기·상설 프로그램을 행사 수 채우기용으로 포함하지 않는 원칙이 반복 확인됐다.
- 행사별 이미지가 전부 포스터가 되는 문제가 반복돼 **실제 현장 활동 사진 우선, 포스터 후순위** 원칙이 강화됐다.
- 검색 가능한 실제 행사 사진이 있는데 생성 이미지를 유지하지 않도록 본문 행사 이미지에서 AI 생성 대체 이미지를 금지했다.
- 마지막 행사 section 직후 글이 갑자기 끝나지 않도록 짧은 마무리 문단을 두는 편집 원칙이 추가됐다.

## 세종 Draft #665 대표이미지 작업

- 한 가지 고정 레이아웃에서 폰트만 바꾸는 비교는 대표이미지 선택에 충분하지 않았다.
- 서로 다른 실제 이미지와 레이아웃을 A01~A06으로 비교하는 HTML 미리보기 방식이 도입됐다.
- 폰트마다 글자 폭이 달라도 의미 단위 줄바꿈과 전체 배치가 흔들리지 않도록 `fixed_semantic_plan`과 `shrink_same_lines_then_reject` 원칙이 추가됐다.
- `10월 축제6곳`은 잘못된 띄어쓰기이며 최종 규칙은 `10월 축제 6곳`이다.
- 사용자는 다음 폰트를 행사 대표이미지 후보에서 제외하도록 명시했다: `HYPMokGak-Bold`, `Gasoek One`, `HYShortSamul-Medium`, `HYGungSo-Bold`, `Headline R`, `한컴 훈민정음_H`, `Magic R`.
- 최종 선택 사례는 A04 레이아웃과 Noto Serif KR 계열이었다. 이 선택은 특정 포스트의 선택 기록이며 모든 행사 글에서 A04를 강제한다는 뜻은 아니다.

## 광주 Draft #666

- 대표이미지의 기본·평범한 고딕 계열 사용을 피하고 시각적 성격이 분명한 한글 폰트를 사용해야 한다는 요구가 강화됐다.
- 행사별 기본 정보는 블로그 안에서 제공하되, 세부 프로그램이 많은 경우 해당 행사 공식 상세페이지를 section 안에 명확한 라벨로 제공하는 방식을 적용했다.

## 유지 원칙

과거 사례에서 나온 다음 항목은 **현행 표준에 이미 반영된 원칙**이며, 사례 자체는 더 이상 규칙 문장에 반복하지 않는다.

- 짧은 날짜 표기
- 대상 월과 직접 관련된 행사만 선정
- 실제 현장 사진 우선, 포스터 후순위
- 행사장 한눈에 보기 카카오맵 + 개별 위치 카드
- 행사별 직접 공식 안내페이지
- 마지막 마무리 문단
- 다중 대표이미지 레이아웃 후보
- 폰트와 무관한 고정 줄 계획
- 로컬 생성에서 끝내지 않고 요청 범위가 WordPress라면 실제 반영·readback까지 완료
