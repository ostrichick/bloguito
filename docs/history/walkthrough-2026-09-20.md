## 1. 주요 작업 내용 요약

### 1) 긴급 버그 수정
- **`run_daily.sh` 인자 오류 수정**:
  - `main.py --all` 인자 미인식 오류를 `main.py --category all --limit 1`로 정상화.
  - `cron.log`가 5MB를 초과할 경우 자동으로 `.old`로 로테이션하는 안전 로직 탑재.
- **WP Super Cache 실제 엔진 가동**:
  - 설정 파일 내 `$cache_enabled = true;`를 적용하여 정적 HTML 캐싱 엔진 활성화.
  - 일반 독자 요청 시 PHP 및 MySQL 쿼리를 생략하고 사전 렌더링된 정적 HTML을 서빙하여 리소스 소모 80~90% 절감.

### 2) 5대 에이전트 파이프라인 지능화
- **Radar Agent (`agents/radar.py`) & `config.py`**:
  - 3대 카테고리(공연, 복지, 건강) 전반의 키워드 풀을 확대.
  - 키워드당 수집 후보를 2건으로 상향(`max_items_per_keyword=2`)하여 팩트 탈락 시 즉시 대체할 수 있는 버퍼 풀 확보.
  - 구글 뉴스 링크와 디코딩된 언론사 원문 링크를 모두 기록하는 듀얼 히스토리 중복 방지 시스템 구축.
- **Curator Agent (`agents/curator.py`)**:
  - 공공기관/언론사의 EUC-KR 및 CP949 웹페이지 수집 시 한글 깨짐을 자동 방지하는 `apparent_encoding` 보정 탑재.
  - 트로트 가수 외 대형 아티스트 및 뮤지컬/행사명을 정밀 추출할 수 있도록 엔티티 파싱 정규식 강화.
- **Copywriter Agent (`agents/copywriter.py`)**:
  - **내부 링크 (Internal Interlinking) 자동 삽입 엔진 탑재**:
    발행 시 `data/published_posts.json` 색인을 실시간 조회하여 동일/유관 카테고리의 기존 글을 본문 최하단에 [🔗 함께 보면 유익한 생활 정보 추천] 카드로 자동 렌더링.
    *(체류 시간 증가 및 구글 검색엔진 크롤링 점수 극대화)*
- **Publisher Agent (`agents/publisher.py`)**:
  - 신규 포스트 발행 성공 시 워드프레스 고유주소를 조회하여 `data/published_posts.json` 색인에 실시간 자동 누적.
- **Designer Agent (`agents/designer.py`) (v3 업그레이드)**:
  - **모드 2 (실사 스톡 사진) 매거진 에디토리얼 타이포그래피 배너 합성**:
    기존 단순 배경 사진에 하단 다크 그라데이션 오버레이 및 나눔스퀘어 볼드 폰트로 카테고리 뱃지와 핵심 타이틀을 합성하여 시각적 전달력 및 검색 클릭률(CTR) 대폭 향상.

### 3) 서버 인프라 & 보안 최적화 (1GB RAM Micro Tuning)
- **MariaDB 버퍼 풀 메모리 캡 적용 (`mysql_custom.cnf`)**:
  - `innodb_buffer_pool_size = 64M`, `max_connections = 50` 설정을 컨테이너 마운트로 고정하여 1GB RAM 환경에서 예기치 않은 메모리 부족(OOM) 방지.
- **워드프레스 보안 차단벽 구축 (`.htaccess`)**:
  - 외부 악성 봇의 대표 타깃인 `xmlrpc.php`를 Apache 웹서버 레벨에서 `403 Forbidden` 차단하여 CPU/메모리 낭비 원천 차단.
- **서버 OS 타임존 정밀 동기화**:
  - 서버 타임존을 UTC에서 **한국 표준시(KST, Asia/Seoul)**로 설정하여 크론 스케줄 및 로그 시간 통일.

### 4) 자동화 및 데이터 백업 구축
- **MariaDB 일일 자동 압축 백업 (`backup_daily.sh`)**:
  - MariaDB 컨테이너에서 직접 스트리밍 덤프 후 gzip으로 실시간 압축 저장 (`/home/ubuntu/backups/`).
  - 최근 7일이 지난 백업 파일 자동 정리(7일 롤링 보관). 2026-09-20부터 운영 서버의 DB 전용 백업 스크립트를 DB·업로드·설정 통합 스냅샷으로 교체; 개인정보가 포함된 백업 파일과 디렉터리 권한을 각각 0600·0700으로 제한하고 3종 SHA256 무결성 검증 실행.
- **Crontab 정식 스케줄 등록**:
  - 매일 새벽 04:00 KST: DB 자동 백업 (`backup_daily.sh`)
  - 매일 아침 08:00 KST: 현재 4대 카테고리 초안 생성 파이프라인(당시 3대였던 과거 이력과 구분) (`run_daily.sh`)

## 3. WhatsApp 원격 제어 비서 시스템 (신규 탑재)

스마트폰의 왓츠앱을 통해 언제 어디서나 블로그와 서버를 원격 통제할 수 있는 경량 브릿지가 구축되었습니다.

- **아키텍처**: `@whiskeysockets/baileys` 순수 웹소켓 멀티 디바이스 클라이언트 (크롬/Puppeteer를 쓰지 않아 1GB RAM 서버에 단 66MB만 점유).
- **상주 형태**: Linux systemd 서비스 (`whatsapp-bridge.service`)로 등록되어 서버 재부팅 시 자동 가동 및 세션 유지.
- **주요 명령어**:
  - `/status` (또는 `상태`): 실시간 서버 메모리, 디스크 여유 용량, Uptime, 도메인 상태 반환
  - `/list` (또는 `초안`, `목록`): 현재 워드프레스에 대기 중인 임시글 목록과 ID 표시
  - `/publish <ID>` (또는 `/발행 <ID>`): 명시적으로 요청된 임시글을 최신 근거·원문·검토 기록 재검사 후에만 공개(캐시 갱신 여부는 별도 점검)
  - `/backup` (또는 `백업`): MariaDB 데이터베이스 즉시 압축 덤프 백업 트리거
  - `/help` (또는 `도움말`): 지원 명령어 도움말 출력
- **당시 보안 통제 주장:** 과거 특정 관리자 번호를 코드와 문서에 고정하고 모든 `fromMe` 메시지를 허용했다. 개인 전화번호는 보존 문서에서 삭제했다. 해당 방식은 이후 안전 개선 대상으로 판정되었으며 현재 권한 정책으로 사용하지 않는다.

  7. **사이트 최상단 고정(`Sticky Post`)**: 심사관이 첫 화면에 진입하자마자 가장 먼저 열람할 수 있도록 메인 전진 배치 완료

## 6. 제2의 마스터 필러 콘텐츠 구축: '정부 환급금 5종 통합 조회' (#139)

독자 체류 시간(Dwell Time)을 극대화하고 세금·공공 환급 분야의 검색 신뢰도를 완성하기 위해, 포스트 **#139**를 4,000자급 마스터 가이드로 신규 발행했습니다.

* **포스트 ID**: [#139] `2026 잠자는 정부 환급금 5종 통합 조회 및 비대면 신청 총정리 (국세·지방세·건강보험·통신비·세금포인트)`
* **카테고리**: 생활 세금/절세 정보 (ID: 102)
* **주요 구성**:
  1. **3초 핵심요약 카드**: 연간 수조 원 방치 환급금 및 5년 소멸시효 골든타임 제시
  2. **5대 국가 공인 환급금 단계별 STEP 안내**:
     - ① 국세 미환급금 (홈택스/손택스 1~3영업일 계좌 입금)
     - ② 지방세 미환급금 (위택스 자동차세 연납 환급 및 계좌 사전등록)

## 7. 최신 모델 우선 + Flash Lite 자동 폴백 & 잔여 사용량 알림 시스템 구축

무료 티어 할당량(일 20회)을 지능적으로 극복하고 파이프라인의 무중단 연속성을 보장하기 위해, 동적 모델 캐스케이딩(Cascading)과 실시간 할당량 알림 엔진을 신규 탑재했습니다.

1. **지능형 모델 캐스케이딩 (`agents/editorial_writer.py`)**:
   - **1순위**: `gemini-3.6-flash` (최신 고지능 모델, 기본 20 RPD)
   - **2순위 (백업)**: `gemini-3.5-flash-lite` (초고속 대용량 모델, **무려 500 RPD**)
   - 1순위 호출 중 `429 (한도 초과)` 또는 `503 (혼잡)` 감지 시 지체 없이 2순위 백업 모델로 즉각 자동 전환하여 글 생성을 중단 없이 완수.
2. **KST 16:00 리셋 기준 일일 할당량 추적기 (`agents/quota_tracker.py`)**:
   - Google AI Studio의 일일 리셋 시점(PDT 자정 = KST 16:00)을 기준으로 모델별 사용 횟수와 잔여량을 `data/quota_usage.json`에 정밀 기록.
3. **발행 완료 알림 메시지 고도화 (`notifier.py`, `main.py`)**:
   - 글이 발행될 때마다 텔레그램/디스코드/왓츠앱으로 **어떤 모델이 글을 썼는지**와 **금일 모델별 잔여 호출 횟수**를 자동으로 보고:
     - 🤖 **작성 AI 모델**: `gemini-3.6-flash` (또는 백업 모델)
     - 📊 **금일 잔여 할당량**:
       - `gemini-3.6-flash`: 잔여 X / 20회
       - `gemini-3.5-flash-lite`: 잔여 Y / 500회
4. **왓츠앱 원격 조회 명령어 탑재 (`whatsapp-bridge/index.js`)**:
   - 왓츠앱에서 언제든 **/quota** 또는 **사용량**을 전송하면 실시간 잔여량을 즉시 답장.
