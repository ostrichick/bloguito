# 공통 편집 시스템 구축 이력 — 2026-09-14

## 요청과 설계 이유

사용자는 긴 프롬프트를 매번 반복하지 않아도 Codex·Antigravity·자동화가 같은 품질 기준을 적용하기를 요청했다. 기존에는 대화 맥락과 여러 MD에 기준이 분산되어 있었고, 파이썬 작성기는 검증된 고정 표만 반환하도록 제한돼 있었다.

공통 문서 `docs/EDITORIAL_SYSTEM.md`와 수치 설정 `agent-publisher/editorial_policy.json`을 만들고 루트 AGENTS.md/GEMINI.md 및 Antigravity always-on 규칙에서 이를 읽도록 했다. Antigravity 규칙 위치는 공식 문서의 `.agents/rules`를 사용했다: https://antigravity.google/docs/rules-workflows

## 구현 범위

- 주제: 현재 WordPress 목록과 대조하고 기존 공개·임시·예약·검토·비공개 글 중복을 제외한다. 일정형 신규 글의 기본 최소 잔여 유효 기간은 30일. 상시형 주제에는 사유를 요구하며 공연/복지의 기간 검사 우회에 사용하지 못한다.
- 수집: 승인 brief의 공식 URL을 직접 읽어 원문·조회시각·해시를 보관한다. 상시형 주제는 뉴스 RSS가 없어도 공식 자료 경로로 진행한다.
- 집필: 첫 답변·설명 문단·FAQ를 구조화하고 각 문단에 원문 인용 및 답한 질문 ID를 연결한다. 이전의 고정 표 제한을 신규 구조화 원고 경로로 대체했다.
- 검토: 작성과 별도 모델 호출로 사실 지지·조건 보존·질문 해결·유효 수명·답변 회피·미확인 주장을 검토한다. 같은 모델을 사용하면 공통 오류가 남을 수 있다.
- 검사: 실제 인용의 존재, 출처 해시/최신성, 원문 수치, 질문 ID, 금지 문구, 검토와 본문/정책의 해시 일치를 검사한다. 세부 오류 위치를 수정 입력으로 전달하고 최대 2회 수정 후 보류한다.
- 등록: 수동과 자동 모두 같은 Publisher를 이용한다. 직전 WordPress 목록 재조회, 동시 등록 잠금, 임시글 강제, 저장 본문 재조회 및 비교, 임시글 색인 기록을 수행한다. 이전 구조의 원고를 Publisher에 직접 전달하면 중단한다.
- 수동 CLI: sources → review → check → publish. publish는 실제 WordPress 목록과 재검토를 요구하고 임의 목록 파일로 등록 검사를 우회할 수 없다.
- 오류: 모델 429/500/502/503/504는 동일 모델에서 최대 3회 시도한다. 인증 오류는 바로 중단한다. 내부 기록은 Git 제외된 data/editorial_runs/에 보관한다.

## 운영 배포

OCI 서버는 아직 예전 작성기·발행기를 사용하고 있었음을 확인했다. 신규 모듈과 필요한 기간/공연/사실 검증 의존 모듈, CLI, 정책, 공통 문서를 배포했다. main.py는 새 작성기와 사전 목록 동기화를 사용하도록 필요한 부분만 패치했다. config.py에는 누락된 DRAFTS_INDEX_FILE/SITE_URL 상수만 보완했다. 비밀정보·기존 서버 주제 목록·예약 시간은 보존했다.

`scripts/install_editorial_release.py`는 대상 파일을 백업하고 import 검증 실패 시 되돌린다. 실제 최초 배포 복구 기록은 운영 앱의 `backups/editorial-20260914T094613Z/manifest.json`에 있다. 백업에 설정이 포함되므로 디렉터리 700, 백업 파일 600 권한을 적용했다. 실제 서버 주소나 키 경로는 이력 문서에 기록하지 않는다.

서버 main.py 전체 실행에서 세 카테고리 모두 유효 신규 후보 0개로 종료했다. 기존 후보는 중복 등의 검사로 제외되며 새 글을 만들지 않았다. 키워드 자동 발굴 서비스까지 구현한 것은 아니므로 에이전트가 조사한 신규 brief가 필요하다.

## 검증과 알려진 한계

- 로컬 전체 회귀 테스트 105개 통과. 신규 편집 검사 28개를 OCI에서도 실행해 통과했다. 최종 배포 복구 기록은 `backups/editorial-20260914T095644Z/manifest.json`이며, 최초 배포 전으로 되돌릴 때는 위 최초 배포 manifest를 사용한다.
- 임시글 강제·저장 본문 비교는 WordPress 명령을 모의해 검증했다. 이번 시스템 구축 중 실제 새 WordPress 글을 등록하지 않았다.
- 실제 서초구 공식 페이지에서 2,852자 본문을 읽었다. 이 테스트는 기존 글과 중복되는 주제를 사용하므로 평가용 빈 목록에서만 실행했고 등록 경로를 호출하지 않았다. 실제 운영 중복 검사를 통과한 주제라고 간주하지 않는다.
- Gemini 3.8 Flash와 gemini-flash-latest 실호출은 503 혼잡 오류로 중단됐다. 기존 Gemini 3.5 Flash 실험에서는 생성된 원고의 수치 근거·FAQ ID 오류를 코드가 차단하고, 필수 사전 전화 조건이 빠진 FAQ를 별도 모델 검토가 차단했다. 수정 후 생성 원고가 별도 의미 검토 및 결정적 검사를 모두 통과했다. 실험 과정에서 원문 5개 미만 범위의 1개처럼 적법한 수량 설명을 허용하도록 검사를 개선했으며 금액·날짜에는 이 예외를 적용하지 않는다.
- 실제 동작을 확인한 3.5 Flash를 운영 기본값으로 명시적으로 선택하고 사용자에게 알렸다. Antigravity의 선택 모델은 변경하지 않았고, 실행 중 자동 모델 전환도 하지 않는다. 정책 JSON뿐 아니라 공통 MD 지침이 변경돼도 기존 검토가 무효화되도록 지침 해시를 결합했다.
- 최종 설정에서 CLI review(실제 모델 호출)와 CLI check를 다시 실행해 모두 ready를 확인했다. 이 결과는 격리된 평가용 원고의 품질 경로 검증이며 추가 WordPress 발행을 뜻하지 않는다.
- 자동 날짜 추출은 명시적 라벨에 보수적이다. 자연어/이미지 자료를 모두 읽는 범용 검증이나 사실의 절대적 진실, 동일 문체·검색 유입을 보장하는 시스템은 아니다.
- Antigravity 규칙 파일은 공식 형식으로 설치했으나 실행 중인 Antigravity UI에서 규칙 로딩을 직접 확인하지 않았다. 동일 프로젝트를 열고 규칙을 읽는 환경에 적용된다.

## 협업 주의사항

작업 시작 시 `copywriter.py`, `main.py`, 신규 `notifier.py`에 다른 작업의 미커밋 변경이 있었다. 해당 알림/읽기 위젯 변경을 보존했으며 이번 커밋에는 main.py의 작성기 import 변경만 선택적으로 포함한다. 알림 코드를 실행하거나 운영 서버에 배포하지 않았다.

과거 MD의 고정 표 발행 설명은 당시 구현 이력이다. 현재 집필·등록 규약은 `docs/EDITORIAL_SYSTEM.md`를 기준으로 한다. 정책 수정 후에는 기존 검토 해시가 무효화되어 다시 검토해야 한다.
