## 남은 검증 기준: 로컬 코드 이후

1. **통합 확인:** 로컬 렌더러 및 관련 테스트에서 단일 요약 라벨, 본문 목차, 앵커, 절차 STEP, 표 헤더·캡션이 반영됐다. 변경을 통합한 코드로 같은 검사를 유지하고 테마·플러그인이 추가하는 목차는 실제 페이지 HTML에서 따로 확인한다.
2. **근거·기능:** 제목·lead·표의 전체 행/셀·FAQ마다 공식 원문·적용 연도·조건·제외·수치 대조를 완료하고 미확인 핵심 사실 0건이어야 한다. 버튼 전부를 직접 열어 라벨과 기능이 일치하는지 확인한다. 해시 검사와 의미 검토 통과는 필요조건이지 사실의 절대 보증이 아니다.
3. **디바이스:** 실제 모바일 360px/390px와 데스크톱, 200% 확대에서 핵심 답·표·FAQ·버튼·목차를 촬영하고 잘림/겹침/가로 탐색·키보드 스크롤을 확인한다. 필요한 경우 보조기술로 테이블의 행열 관계를 확인한다. 확인하지 못하면 미검증으로 표시한다.
4. **원고 시험:** 승인된 기존 글 한 편을 선정할 때 공식 최신 근거 대조 → 원본 백업/해시 → 구조화 bundle와 독립 검토 → 사전 미리보기 → 사용자 승인에 따른 안전 갱신 → 실제 게시 HTML 검사를 차례대로 진행한다. 신규 글은 draft만 생성한다.
5. **효과 측정(선택):** 소수의 독자에게 조건·신청 링크·예외 문의처 찾기 과제를 실시하고 성공/소요 시간/오해를 기록한다. Search Console·실제 클릭·광고 수익은 계측된 값과 기간이 있을 때만 비교하고 작은 표본을 전체 독자나 수익 개선의 증거로 일반화하지 않는다.
