# Bloguito 도시별 월간 행사 포스트 표준

이 문서는 **한 도시·지역의 여러 행사, 축제, 공연, 전시, 체험을 한 달 단위로 비교하는 일정형 포스트**에만 적용하는 전용 규약이다. 출처 신선도, SEO, CTA 일반 원칙, WordPress CAS 저장, 공통 문체, 공통 QA처럼 모든 글에 적용되는 규칙은 [EDITORIAL_SYSTEM.md](EDITORIAL_SYSTEM.md)를 따른다. 이 문서는 그 공통 규칙을 반복하지 않고 **행사 포스트에서 달라지는 부분만** 정의한다.

현재 자동 검증 호환성을 위해 bundle의 `brief.event_post_standard_version` 값은 계속 `1`을 사용한다. 이 문서의 편집 규칙 개정은 해당 숫자를 임의로 올리는 마이그레이션을 의미하지 않는다.

과거 작업에서 이 규칙이 생긴 배경과 사례는 [행사 포스트 표준 작업 사례](history/EVENT_POST_STANDARD_CASES-2026-10-02.md)에 분리해 기록한다.

## 1. 규칙 강도

이 문서에서는 규칙을 세 단계로만 구분한다.

- **MUST**: 행사 포스트 완성 조건. 충족하지 않으면 저장·승인 전에 수정한다.
- **SHOULD**: 특별한 이유가 없으면 따른다. 예외를 적용하면 이유가 설명 가능해야 한다.
- **MAY**: 독자 판단에 실제 도움이 될 때만 선택적으로 사용한다.

## 2. 적용 대상

### MUST

- 한 도시·지역의 서로 다른 행사 2개 이상을 한 글에서 비교한다.
- `brief.content_type = "dated"`와 `temporal_source.multi_event_schedule = true`를 사용한다.
- 각 `event_entries[].name`은 상세 section 하나의 `event_name`과 정확히 1:1로 연결한다.
- 콘서트 한 공연의 지역별 회차 목록이 아니라 **지역 행사·축제·전시·공공 체험을 묶은 월간 일정 가이드**에 적용한다.

## 3. 행사 선정

### MUST

- 대상 도시에서 실제로 열리는 행사여야 한다.
- 대상 월에 실제 행사 일정이 존재해야 한다.
- 현재 연도 공식 source에서 최소한 행사명, 시작일, 종료일, 장소를 확인한다.
- 제목에 `6곳`, `7곳`처럼 행사 수를 썼다면 실제 상세 section 수와 정확히 일치해야 한다.
- 대상 월과 관계없는 행사, 종료된 행사, 개최 여부가 불명확한 행사, 숫자를 채우기 위한 상설 프로그램은 제외한다.
- 공식 자료에 없는 비용, 운영시간, 예약 상태, 무료 여부, 프로그램을 추정해서 채우지 않는다.
- 공통 행사 개수나 본문 단어 수를 품질 게이트로 고정하지 않는다.

### SHOULD

- 방문 목적이 서로 다른 행사들을 적절히 섞는다. 예: 대표축제, 공연, 전시, 가족 체험, 야외행사.
- 장기 전시·상설 프로그램은 대상 월에 특별 일정, 종료일, 별도 프로그램 등 **그 달에 소개할 이유가 분명할 때** 포함한다.
- 행사 개수를 맞추기 위해 가치가 낮은 후보를 추가하지 않는다.

## 4. 글의 기본 순서

### MUST

도시별 월간 행사 글은 다음 순서를 기본으로 한다.

1. 제목
2. 짧은 lead
3. `한눈에 보기` 행사 비교
4. **행사장 한눈에 보기 카카오맵**
5. 행사별 상세 section
6. 짧은 마무리
7. 필요한 경우 FAQ
8. 공식 출처

별도 `추천 행사`, `어떤 행사를 고를까` section이 상세 section과 같은 내용을 반복하면 만들지 않는다.

## 5. 한눈에 보기

### MUST

- 첫 overview는 `kind: "overview"`로 작성한다.
- 열은 **`날짜 | 행사 | 주요 볼거리 | 장소`** 순서의 4열로 고정한다.
- 날짜는 짧게 쓴다. 예: `10/9(금)`, 같은 달 기간은 `10/9(금)~11(일)`, 달이 바뀌면 `10/30(금)~11/1(일)`.
- `2026-10-09`, `2026.10.09`, `10.9.(금)`처럼 source별 원문 날짜 표기를 한 표 안에 섞지 않는다.
- 긴 설명, `미정`, `행사별 상이`, `주요 일정별 상이` 같은 자리 채우기 문구를 표에 넣지 않는다.
- 운영시간·예약·세부 가격은 overview에 억지로 압축하지 말고 상세 section에서 설명한다.

## 6. 행사장 한눈에 보기 카카오맵

### MUST

- overview 바로 뒤에 **글에 포함된 모든 행사장을 한 화면에서 비교하는 인터랙티브 카카오맵**을 둔다.
- 최종 `event_name` 행사 전체가 marker 또는 grouped marker에 빠짐없이 연결돼야 한다.
- 각 marker에서 최소한 **행사명, 일정, 행사장명, 해당 상세 section으로 이동하는 anchor**를 확인할 수 있어야 한다.
- 행사장명·주소·좌표는 해당 행사 공식 source와 실제 지도에서 검증한다. 도시 중심 좌표나 추정 좌표를 행사 위치로 대신하지 않는다.
- 같은 장소의 여러 행사는 하나의 marker로 묶을 수 있지만 각 행사명·일정·본문 anchor를 모두 선택할 수 있어야 한다.
- 모든 marker가 최초 화면 안에 들어오도록 자동 영역 맞춤을 사용한다.
- 지도는 반응형이어야 하며 desktop의 drag/zoom과 mobile의 marker 선택·확대축소가 페이지 스크롤을 심하게 방해하지 않아야 한다.
- SDK 로딩 실패나 JavaScript 차단 시에도 각 행사 section의 **카카오맵 위치 보기, 네이버지도 위치 보기** 링크는 사용할 수 있어야 한다.
- 도시별로 지도 HTML, SDK 로딩, API key, marker script를 복제하지 않고 공통 renderer/component를 재사용한다.

### SHOULD

- 지도 section 제목은 `행사장 한눈에 보기`처럼 기능이 바로 드러나게 한다.
- 단일 행사장만 있는 특수한 경우 지나치게 확대하지 않고 읽기 좋은 기본 zoom을 사용한다.

## 7. 행사별 상세 section 형식

### MUST

각 행사는 아래 순서를 유지한다. **날짜·장소만 반복하는 section은 완성된 행사 소개로 보지 않는다.**

```text
문단 제목

소개 이미지

(필요한 경우) 사진 출처

소개 내용 본문

(필요한 경우) 작은 테이블로 다양한 일정 소개

행사 공식 안내페이지 링크 박스

행사장 위치: 행사장명
주소: 공식 source에서 확인한 경우에만 표시

카카오맵 위치 보기 | 네이버지도 위치 보기
```

세부 계약은 다음과 같다.

1. **문단 제목**
   - 공식 행사명을 중심으로 짧고 명확하게 쓴다.
   - `event_name`과 의미가 일치해야 한다.

2. **소개 이미지**
   - 제목 바로 아래에 대표 이미지 1개를 둔다.
   - 실제 행사 활동을 이해하는 데 도움이 되는 사진을 우선한다.

3. **사진 출처**
   - 출처·촬영연도·참고 성격을 독자가 알아야 할 때 이미지 바로 아래에 표시한다.
   - 이전 회차 사진이면 예: `2025 행사 현장, 2026 행사 분위기 참고`처럼 연도와 참고 성격을 함께 쓴다.
   - `open_license`, `permission_granted`, `source_attributed`처럼 재사용·귀속 근거를 독자가 확인할 필요가 있는 이미지는 `사진 출처` 링크를 표시한다.
   - Bloguito가 권리를 보유한 `site_owned` 현재 회차 이미지는 별도 외부 `사진 출처` 링크를 생략할 수 있다. caption 자체는 유지한다.

4. **소개 내용 본문**
   - 이 행사가 무엇인지, 무엇을 볼 수 있는지 또는 무엇을 할 수 있는지를 먼저 설명한다.
   - 비용, 예약, 운영시간, 대상 조건 중 방문 결정에 필요한 확인된 정보가 있으면 함께 설명한다.
   - 공식 자료에서 확인되지 않은 추천 대상·주차 팁·프로그램을 만들어 넣지 않는다.

5. **작은 일정표**
   - 여러 날짜·회차·장소·프로그램을 실제로 비교해야 할 때만 사용한다.
   - 같은 값이 반복되는 형식용 표는 만들지 않는다.

6. **행사 공식 안내페이지 링크 박스**
   - 각 행사 section에 반드시 둔다.
   - 해당 행사의 공식 상세페이지, 주최기관 행사 상세페이지, 지자체 행사 상세페이지, 공식 SNS 게시물 순으로 직접적인 페이지를 우선한다.
   - `공식 홈페이지`처럼 모호한 라벨 대신 `세종한글축제 공식 일정 보기`처럼 도착 내용을 구체적으로 쓴다.
   - 예약·신청·예매·구매 기능 링크가 따로 있으면 공통 CTA 정책에 따라 별도 행동 링크로 구분한다.

7. **행사장 위치 블록**
   - `행사장 위치: 행사장명`을 표시한다.
   - `주소:`는 공식 source에서 실제 주소를 확인한 경우에만 표시한다.
   - 주소가 확인되지 않았다고 임의 도로명주소를 만들지 않는다.
   - `카카오맵 위치 보기`, `네이버지도 위치 보기` 링크를 함께 제공한다.

## 8. 본문 행사 이미지

### MUST

- 행사별 본문 이미지로 새 AI 생성 이미지, Pillow 도형 이미지, 임의 일러스트를 만들지 않는다.
- 검색 결과 이미지 자체를 출처로 취급하지 않고 원문 페이지와 재사용 조건을 확인한다.
- 이전 회차 사진을 현재 회차 사진처럼 보이게 쓰지 않는다.
- 상업적 재사용이 불분명한 이미지를 블로그에 복제 업로드하지 않는다.
- 이미지가 없는 section을 개수 맞추기용 임의 이미지로 채우지 않는다.
- 실제 행사 사진을 찾을 수 있는데 포스터부터 우선 채택하지 않는다.

### SHOULD

사용 가능한 이미지의 우선순위는 다음과 같다.

1. 현재 회차 주최측·지자체·공공기관의 실제 공연·체험·전시·부스·관람객 사진
2. 공식 행사 갤러리의 실제 현장 사진
3. 한국관광공사·공공 관광 아카이브의 실제 행사 사진
4. 직전 회차의 실제 활동 사진
5. 재사용 조건을 확인한 언론 사진
6. 적합한 실제 사진을 찾지 못했을 때의 공식 고해상도 포스터

즉, **포스터는 실제 현장 사진보다 후순위**다.

## 9. 대표이미지

공통 대표이미지의 텍스트 정확성, 안전 여백, 한글 깨짐 방지, 업로드 전 시각 검수는 `EDITORIAL_SYSTEM.md`와 `editorial_policy.json`을 따른다. 도시 행사 글에는 다음 추가 규칙을 적용한다.

### MUST

- 최종 선택 전 **서로 다른 레이아웃 후보를 최소 5개** 만든다.
- 같은 레이아웃에서 폰트만 바꾼 이미지는 별도 레이아웃 후보로 계산하지 않는다.
- 후보끼리는 사진, 사진 영역, 텍스트 위치, 카드 구조, 정렬, 오버레이 중 하나 이상이 실질적으로 달라야 한다.
- 메인 문구의 줄 계획은 폰트 적용 전에 고정한다. 폰트 폭 때문에 임의 재줄바꿈하지 않는다.
- `10월 축제 6곳`처럼 한국어 띄어쓰기를 정확히 지킨다.
- 선택된 후보와 폰트 조합을 실제 WordPress 대표이미지에 반영해야 작업 완료로 본다.
- 행사 대표이미지의 허용 후보, 제외 후보, 현재 기본 폰트는 `editorial_policy.json`의 `candidate_font_families`, `excluded_font_families`, `brand_*_font_family` 값을 단일 machine source of truth로 사용한다. 문서에 별도 폰트 목록을 복제하지 않는다.

### SHOULD

- 1200×675, 16:9를 사용한다.
- 도시, 월, 행사 수를 작은 썸네일에서도 바로 알아볼 수 있게 한다.
- 실제 행사·전시·공연 분위기를 보여 주는 사진을 우선 사용한다.
- 대표이미지 후보 비교용 HTML에서는 여러 레이아웃과 허용 폰트를 빠르게 바꿔 볼 수 있게 한다.

## 10. 마무리와 FAQ

### MUST

- 마지막 행사 section 뒤에는 글을 바로 끝내지 않고 짧은 마무리 문단을 둔다.
- 마무리는 대형축제, 전시, 공연, 체험 등 성격 차이를 짧게 정리하되 앞 내용을 장황하게 반복하지 않는다.

### MAY

- 본문만으로 해결되지 않는 실제 추가 질문이 있을 때 FAQ를 둔다.
- 예: 무료 행사, 사전 예약 행사, 아이와 할 수 있는 체험, 같은 날 일정 비교.
- 표나 본문에 이미 명확한 정보를 그대로 질문형으로 반복하는 FAQ는 만들지 않는다.

## 11. 사람·브라우저 완료 체크

### MUST

- desktop/mobile 실제 렌더에서 **제목 → 이미지 → 필요 시 출처 → 본문 → 필요 시 작은 표 → 공식 안내 링크 박스 → 위치·지도 링크**의 시각적 순서가 자연스러운지 확인한다.
- 카카오맵 marker가 행사장 위치와 맞고, marker 선택·본문 anchor 이동·모바일 확대축소가 실제로 동작하는지 확인한다.
- 각 행사 사진이 해당 활동을 보여 주고 화질·crop이 충분한지, 더 적절한 실제 사진을 두고 포스터를 쓴 것은 아닌지 확인한다.
- 공식 안내 링크와 카카오맵·네이버지도 링크를 눌러 실제 의도한 목적지로 이동하는지 smoke test한다.
- 대표이미지 한글, 띄어쓰기, 줄바꿈, crop을 실제 최종 파일에서 확인한다.

행사형 포스트의 핵심 품질 기준은 행사 수나 글자 수가 아니라 **독자가 날짜, 장소, 볼거리, 비용·예약 조건, 행사장 위치를 빠르게 비교하고 실제 방문 여부를 판단할 수 있는가**다.
